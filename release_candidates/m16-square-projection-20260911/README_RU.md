# M16: проекция уравнений без потери настоящих решений

Дата: 11 сентября 2026. Статус: исследовательский кандидат, не Lean-доказательство.
Исходный пакет сохранён в PR 436 проекта KeyAI. Новые исходники не изменяют
архивы предыдущих проходов или канонические реестры доказательств.

## Результат

Вместо добавления случайного ограничения к 15 параметрам рассмотрена случайная
линейная проекция 16 остаточных уравнений в 15 уравнений. Она сохраняет каждое
настоящее решение при любом допустимом выборе проекции. При равномерном выборе
ядра среднее число добавленных допустимых решений над исходным конечным полем
строго меньше единицы. Это не граница числа геометрических решений над
расширениями поля, степени устранения или стоимости их нахождения.

Утверждения о случайных проекциях ниже применимы к любому отображению конечных
множеств указанного размера. Они не являются новым общим методом решения
полиномиальных систем. Работа Duff, Hein, Sottile рассматривает сертификацию
через квадратные подсистемы над комплексными числами; её численные гарантии
не переносятся здесь на конечные поля. См. `SOURCES.json`.

## 1. Точная постановка и сохранение решений

Пусть D является произвольным подмножеством F_p^d, а
S=(S_0,...,S_d):D -> F_p^(d+1). Для нашей карты d=15. Через Z обозначим
{x in D:S(x)=0}. Допустимость, например условие взаимной простоты, остаётся
отдельной проверкой и не отбрасывается.

Выбираем равномерную прямую [v] в P^d(F_p), где v ненулевой. Практический
равномерный выбор: взять равномерный ненулевой вектор и нормировать его первый
ненулевой элемент к единице. Каждая прямая имеет ровно p-1 таких векторов.
Нельзя выбирать номер ведущей позиции равномерно: это другое распределение.

Выбрав j с v_j != 0, задаём d уравнений:

    T_i(x)=v_j*S_i(x)-v_i*S_j(x)=0, i != j.

Их совместное выполнение эквивалентно S(x) in span(v). Поэтому Z входит в
множество решений T для КАЖДОЙ проекции. В пространстве коэффициентов новое
ограничение не появляется: удаляется одна независимая комбинация уравнений.

## 2. Точное среднее число посторонних рациональных решений

Число прямых N=(p^(d+1)-1)/(p-1)=1+p+...+p^d.
Для фиксированного x вне Z вектор S(x) ненулевой и принадлежит ровно одной
прямой. Поэтому вероятность T(x)=0 равна 1/N. Линейность ожидания даёт

    E_v |{x in D:T(x)=0, S(x)!=0}| = (|D|-|Z|)/N < 1.

Независимость событий для разных x не нужна и не предполагается. Полученное
число не является вероятностью существования исходного разложения. Проекция
может иметь много посторонних корней для отдельного выбора v. Также она
может создавать большое число решений над расширениями поля. Решатель должен
проверять все исходные уравнения и допустимость, а не принимать T=0 как ответ.

Условное следствие: если |Z|=z>0 и имеется процедура РАВНОМЕРНОГО выбора одного
допустимого рационального корня T, то средняя вероятность, что он настоящий,
равна E[z/(z+X)] и по выпуклости не меньше

    z/(z+E[X]) > z/(z+1) >= 1/2.

Это условие на ещё не построенную процедуру. Произвольный корень, возвращённый
алгоритмом устранения, не обязан иметь равномерное распределение; затраты на
поиск рациональных корней этой формулой не оценены.

## 3. Сохранение локального ранга

В настоящем решении x пусть J_S имеет полный столбцовый ранг d. Якобиан
квадратной подсистемы невырожден ровно тогда, когда span(v) не содержится в
im(J_S). В d-мерном образе находится 1+p+...+p^(d-1) прямых, поэтому

    Pr(rank J_T=d) = p^d/N = (1-1/p)/(1-1/p^(d+1)).

Вероятность потери ранга строго меньше 1/p. Даже в таком случае настоящее
решение не теряется: оно только становится вырожденным в выбранной записи.
Для M16 применение условно опирается на доказательство ранга 15 предыдущего
пакета и все его условия допустимости. Его формализация в Lean не выполнена.

## 4. Почему случайное сечение параметров не заменяет проекцию уравнений

Дополнительное случайное аффинное уравнение в параметрах сохраняет каждое
фиксированное решение с вероятностью 1/p. Для конечного множества из M
сертификатов вероятность сохранить хотя бы один не больше M/p. По прежнему
соответствию сертификатов неупорядоченным разложениям получаем условную
усреднённую верхнюю границу

    binomial(567054+15,16) / ((n-567054-1)*p) ~ 2^(-250.43981).

Здесь цель равномерна вне точки бесконечности и самой факторбазы; p и n имеют
обычные различные значения для secp256k1. Это ограничение независимого
случайного сечения, не запрет структурного выбора коэффициентов по цели.
Проекция уравнений не уменьшает число параметров и потому не платит этот
штраф. Она также не обещает быстрое решение оставшейся квадратной системы.

## 5. Что реально вычислено

Сначала `PLAN.json` зафиксировал малый пример из предыдущего архива:
p=97, D=3, q=4, R=(17,19), параметры (a1,a2,b0). Выполнен полный контрольный
перебор всех 97^3=912673 наборов коэффициентов, не новый масштабируемый поиск.

- Допустимы 893952 набора; одно настоящее допустимое решение.
- Ровно 922180 проектирующих прямых; среднее число посторонних допустимых
  корней равно 893951/922180.
- У 361599 прямых нет постороннего допустимого рационального корня.
- Полная гистограмма сохранена в `RESULTS.json`; максимум равен 29.
- Векторизованный расчёт сверён с отдельной скалярной полиномиальной
  реализацией в 258 точках, включая все найденные исходные нули.
- Полнота множества настоящих ответов сверена перебором всех мультимножеств
  точек факторбазы с непосредственным групповым сложением.

Единственное разложение состоит из четырёх повторений (35,28); это прежний
простой случай 4P=R, не новый трудный криптографический результат. Контрольный
перебор не передаётся никакому заявляемому быстрому решателю: такого решателя
этот пакет не содержит. Другие проверки и оракулы имеют общего автора.

Отдельно над p=3,5,7,11 исчерпывающе проверены проекции небольшой системы с
двумя известными невырожденными нулями. Все истинные решения сохраняются;
точные средние и доли сохранения ранга совпадают с формулами разделов 2 и 3.

## 6. Воспроизведение

Python 3.10+ и NumPy; точная проверенная версия зависимости в requirements.txt.

    python projection_check.py --check
    python -m unittest discover -p 'test_*.py' -v

Десять регрессионных тестов. --check повторяет вычисления без перезаписи
RESULTS.json; время исключено только из сравнения воспроизводимости, все
математические поля сравниваются. Для явного нового отчёта используется
--write. Первая ошибка сериализации и её исправление описаны в ATTEMPTS.json.

## 7. Следующий проверяемый вопрос

Можно ли для этой квадратной подсистемы находить хотя бы один допустимый
рациональный корень дешевле, чем для исходной переопределённой системы,
включая расходы проверки и неуспешные проекции? Нужен отдельный согласованный
по распределению целей и вероятности успеха эксперимент. Настоящий пакет
доказывает свойства преобразования и проверяет их на конечных примерах, но
не отвечает положительно на вопрос о стоимости поиска M16.

## 8. Проверка стоимости: первое сравнение не показало ускорения

После исходного плана отдельно зафиксирован `SYMBOLIC_PLAN.json`: тот же
малый пример, одинаковые порядок переменных и grevlex-алгоритм, один вектор
(62,61,94,42), полученный из заранее указанной хеш-строки. Это детерминированный
контроль, а не случайная статистическая выборка. Оба запуска завершились.

| Величина | Исходные 4 уравнения | Проецированные 3 уравнения |
|---|---:|---:|
| Максимальная входная степень | 6 | 6 |
| Число полиномов полученного базиса | 3 | 27 |
| Максимальная ВЫХОДНАЯ степень базиса | 1 | 8 |
| Размерность нульмерной фактор-алгебры | 1 | 80 |
| Наблюдаемое время базиса при повторе | 1,764 с | 2,429 с |
| Допустимые рациональные корни, точный перебор | 1 | 3 |

Размерность фактор-алгебры вычислена подсчётом стандартных мономов по ведущим
мономам базиса; она не подменяется числом различных корней. Полный перебор
подтвердил: исходный корень сохранён, добавлены ровно два допустимых рациональных
корня. Оба посторонние, и должны быть отвергнуты исходной системой.

Таким образом, малая средняя численность лишних рациональных корней не гарантирует
малой алгебры, с которой работает общий символьный решатель. В этом конкретном
примере проекция увеличила промежуточный выход и время; выигрыша не получено.
Максимальная выходная степень не является измерением solving degree.
Исходные времена первого запуска сохранены в `SYMBOLIC_HISTORY.json`.

Дополнительный тест фиксированной проекции доводит регрессионный набор до
10 тестов. Для воспроизведения диагностических запусков:

    python run_symbolic.py original
    python run_symbolic.py projected

Каждый вызов явно записывает свой новый отчёт. Бюджет дочернего процесса 35 с
был одинаковым для обоих вариантов; в проведённых запусках он не достигнут.
