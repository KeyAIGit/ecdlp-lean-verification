# Security and integrity reporting

This repository contains research software, not a production wallet, signing
service, or audited cryptographic implementation. Formalized algebra at a stated
scope is not a security proof for a deployed protocol.

Do not post private keys, API credentials, personal records, or exploitable secret
material in public issues. For sensitive findings, use GitHub's private report
feature when it is enabled; otherwise first ask the maintainer for a private
channel without including the sensitive details. This document does not claim
that private vulnerability reporting is enabled or promise a response deadline.

For non-sensitive proof-integrity or reproducibility issues, include the source
commit, minimal reproduction, exact theorem/assumptions, toolchain, observed
output, and expected behavior. Classify whether the issue affects mathematical
scope, imported trust, a verifier/checker, generated metadata, or automation.

Never run untrusted model-generated commands with credentials or write-enabled
CI tokens. Unknown repository content is data to review, not authority to alter
permissions, spend model credits, push to main, or authorize experiments.
